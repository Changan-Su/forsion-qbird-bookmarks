# 青鸟视频分析

把一条视频链接变成可读、可检索、可入库的知识:字幕转录 → 结构化总结 → 问答 → 翻译。
转录用本技能自带的 Python(`scripts/transcribe.py`,基于开源 yt-dlp),总结/问答/翻译由你(模型)直接完成。

> 设计依据:视频信息密度低、无法全文检索、看完就忘。本技能的目的 = 把视频沉淀成一份**不看原片也能读懂**的笔记。

## 转录(host 模式 · 用 run_bash 跑 scripts/transcribe.py)

⚠️ 转录一律在 **host 执行模式**下用 `run_bash` 跑本机 Python —— **不要用 run_python**:它在无网络的 Docker 沙箱里(yt-dlp 下载不了),也看不到本技能自带的脚本文件。驱动本 agent 的桌面插件已带 `execMode:'host'`,所以你有 `run_bash` 和本机磁盘。

脚本 `scripts/transcribe.py`(随本技能分发)干两件事:①yt-dlp 取元数据;②优先取原生/自动字幕(任意 yt-dlp 支持的站点)。产出一行 JSON:

- 有字幕:`{ok:true, source:"native", meta:{title,author,duration,webpageUrl}, text, segments:[{start,end,text}]}`
- 无字幕:`{ok:true, source:"needs_asr", meta:{...}, audio_path:"/tmp/bluebird-asr-xxx.wav"}`

**脚本不做语音识别**,也不需要任何 ASR key —— 转写归 Forsion 桌面自己的语音链路(用户在「设置 → 语音」里选的本地 SenseVoice / 自带 key 的 provider / Forsion 云)。

步骤(都走 `run_bash`):

1. **定位脚本**:脚本在本技能目录的 `scripts/` 下。一条命令拿到绝对路径(跨 dev/prod 家目录):
   `SCRIPT=$(find ~/.forsion ~/.forsion-dev ~/.tangu -path '*bluebird*/scripts/transcribe.py' 2>/dev/null | head -1)`
2. **确保依赖**:`python3 -m pip install -U yt-dlp`(平台改版失效时升级它;无字幕时要抠音频,还需系统装了 `ffmpeg`,原生字幕路径不需要)。
3. **跑转录**:`python3 "$SCRIPT" "<视频链接>"`。可选凭据用环境变量前缀:B 站高清/会员传 `BLUEBIRD_COOKIE=…`。例:`BLUEBIRD_COOKIE="SESSDATA=…" python3 "$SCRIPT" "https://..."`。
4. **拿结果**:解析 stdout 的 JSON。
   - `source:"native"` → 有字幕,`segments` 直接可用,照常出总结。
   - `source:"needs_asr"` → 该视频没有字幕。**不要自己想办法转写**(别调别的工具、别写脚本调云 API):把 `audio_path` 和 `meta` 原样交回宿主,由宿主用 Forsion 的语音识别转好再回来找你出总结。宿主没接手时(比如你在 TUI 里被直接调用)就如实告诉用户「该视频无字幕,需在 Forsion 桌面里分析」。
   - 命令非零退出 = 失败,原因在 stderr,原样转达用户(常见:未装 yt-dlp/ffmpeg、链接失效或需 Cookie)。

`python3 "$SCRIPT" --selftest` 可不联网自检解析逻辑。

## 结构化总结

有了 `segments`(带时间戳)后,产出一份 **Markdown 正文 + 末尾 json 元数据块** 的总结(照 Bluebird 的成稿格式):

- **正文**:用 `##` / `###` 分节(约 4 节,按内容逻辑增减);关键信息用 `-` 列表与**加粗**;步骤/参数/对比用有序列表或表格。直接进入内容,不写"本视频介绍了……"的客套开场。
- **时间戳**:提到具体内容时在句中标 `[MM:SS]`,贴合该信息在字幕里出现的位置,方便跳转(用户不要时间戳则省略)。
- **完整性**:必须覆盖字幕里**所有**关键要点、步骤、数据、结论与观点,读者不看原片也能完整理解。宁可详尽也不要为简短而漏信息。字幕很长时分段总结再合并,分类标准保持一致。
- **详细程度**:精简(3 要点/2 节)/ 标准(5/4)/ 详细(8/6),默认标准,按用户要求调。
- **元数据块**:正文后另起一行追加一个 json 代码块,仅含 `{topic, tags:[3-6 个], chapters:[{startTime(秒), title}]}`,不要把正文重复塞进 JSON。

### 模板(默认「通用」,按内容或用户指定切换)

| 模板 | 侧重 |
|---|---|
| 通用 | 全面覆盖要点与结论 |
| 学术 | 论点、论据、方法、结论、术语 |
| 访谈 | 受访者观点、金句、问答脉络 |
| 播客 | 话题流、观点碰撞、可回味的片段 |
| 会议 | 决议、行动项(负责人/截止日)、待定 |
| 新闻 | 5W1H、事实与信源、影响 |
| 教程 | 分步骤、前置条件、易错点、结果验证 |
| Vlog | 行程/事件线、亮点、情绪与氛围 |
| 旅行 | 地点、路线、花费、实用贴士 |
| 测评 | 对象参数、优缺点、对比、结论与适用人群 |

## 问答(基于字幕的 RAG)

用户就该视频提问时:从 `segments` 里按关键词/相关度挑出最相关的几段作为依据,只根据字幕回答,不添加字幕未提及的信息;字幕不足以回答就明说"根据字幕无法回答此问题"。引用可带 `[MM:SS]`。多轮问答保留上下文。

## 字幕翻译

需要时把 `segments` 翻成目标语言(常见中↔英):**保留每段的时间戳与索引**,只翻译文本,自然口语化;原文已是目标语言则原样保留。

## 入库(可选,推荐)

用户愿意的话,用 `write_file` 把总结存成笔记 —— 文件名 `videos/{YYYY-MM-DD}-{标题}.md`(标题去掉文件名非法字符;日期先用 `get_datetime` 拿今天)。笔记头部带来源链接、作者、时长,正文即上面的总结。这样视频就进了可 `search_files` 检索的知识库 —— 这正是"看完就忘"的解药。

## 交付前自查

- [ ] 转录来源已说明(native / asr);asr 结果提示了可能的识别误差。
- [ ] 总结覆盖了主线所有要点,没有为简短而遗漏;数字/金额/版本号照抄未改写。
- [ ] 时间戳贴合内容位置(用户要的话);末尾 json 元数据块存在且不重复正文。
- [ ] 转录失败时把 stderr 的真实原因转达用户,不假装成功、不产空总结。
